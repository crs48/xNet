Build on the same data

xNet’s substrate is the data layer under the app. Like Lego pieces, its records share a common fit: you can combine them, extend them, and build a different tool around them.

  1. Nodes

    Reusable records

    A task, a contact, a page. Each record has an ID. Relations connect records across your workspace.

  2. Schemas

    A shared structure

    Title, status, project. Define fields and relations. Add fields in your namespace or create a new type.

  3. Views

    Different ways to work

    A table, a board, your own app. Read and edit the same records through a different interface.

task.schema.ts 
import { defineSchema, text, checkbox }
  from '@xnetjs/data'

const Task = defineSchema({
  name: 'Task',
  namespace: 'xnet://my-app/',
  properties: {
    title: text({ required: true }),
    done: checkbox({ default: false })
  }
})

A schema defines the data. Your interface decides how to display it.

How storage, sync, and permissions work

Local storage. The workspace keeps a copy on your device. Offline changes sync when connected.

Signed changes. Structured edits form a signed, hash-linked log. Peers can check who signed an edit and detect changes to it.

Merge rules. Yjs merges document edits; structured fields use last-writer-wins rules. Grants govern sharing and access.
